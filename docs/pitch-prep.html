InfraSentinel, explained so anyone on the team can answer.

Read sections 1–4 at least once each. Then use the Q&A practice until every question feels easy. The bold sentences are the ones to say out loud.

The one-line pitchInfraSentinel finds the security problems inside a small organization's servers and laptops, explains each one in plain language, and tells the owner exactly what to do, including when to call a professional.
The 30-second versionSmall businesses, schools and clinics run their apps on secure clouds, but the security of their own servers is still their job: passwords, updates, open services, admin rights, backups. They have no security staff to check these. InfraSentinel installs a small read-only checker with one command, finds the problems, ranks them by what matters to that organization, and gives simple fix steps. A security-tuned AI that runs privately on our own machine answers follow-up questions. The owner sees what to fix first, who should fix it, and proof when it's done.

The problem and who it's for

The problem

Security tools give long lists of technical alerts. A school office manager or a shop owner can't tell which alert could stop billing tomorrow, or how to fix it. There is no one on staff to translate.

Who it's for

Small businesses and startups, schools, colleges, and clinics with one or two IT people or none. People who are not computer experts.

The cloud argument (judges asked this before)

Cloud security is shared. AWS, Azure and Google secure the data centres and their platform. The customer is still responsible for what they put on it: accounts and passwords, settings, updates, which services are open, admin rights, backups. That half is where small teams fail, and that is the half InfraSentinel covers.

Say it like thisYour cloud provider protects the cloud. We help with your part of it.

The owner's journey, step by step

  1. Sign in or create an account for the organization. Each organization only ever sees its own machines.
  2. Connect a server or PC. Pick Linux/Mac or Windows, copy one command, paste it on that machine. It works from Command Prompt, PowerShell or a Linux terminal.
  3. The checker reads settings and logs (never changes anything) and sends a report within seconds.
  4. Problems appear, most serious first. Each has simple steps and a label: You can do this Your IT person Call a professional.
  5. Ask the AI anything in plain words. With web search on, it reads current guides and cites them.
  6. Fix it, then prove it. A fix only counts as done when proof is recorded, such as a clean re-scan.
  7. Scan now from anywhere. If the owner allowed it, the machine re-checks itself within about 15 seconds.

Why "Scan now" works through firewalls

The checker on the machine asks our server "anything for me?" every 15 seconds. That is an outgoing connection, like opening a website, so no ports need to be opened on the customer's network. We never connect in to their machine.

What the checker looks at

All checks are read-only. Some need administrator rights; without them the checker says exactly what it skipped.

Linux servers

  • Services open to the network
  • SSH: password logins, direct root login
  • Security patches waiting, automatic updates
  • Operating system still supported
  • Firewall turned on
  • Extra admin accounts, admin group size
  • Password file permissions, empty passwords (admin)
  • A backup tool or schedule
  • Logs, last 7 days: failed sign-ins and where from, root sign-ins, failed sudo, new accounts, system errors

Windows PCs

  • Windows Firewall for each network type
  • Microsoft Defender on, definitions up to date
  • Days since the last Windows update
  • Windows version still supported
  • Remote Desktop and Network Level Authentication
  • Old SMBv1 file sharing (WannaCry)
  • Admin accounts, Guest, built-in Administrator, UAC
  • Password length and lockout rules
  • BitLocker disk encryption (admin), backups
  • Event logs: failed sign-ins (4625), remote sign-ins (4624), new accounts (4720)

Every problem is filed under one of 15 kinds of weakness: weak passwords, outdated software, missing patches, broken access control, SQL injection, cross-site scripting, misconfiguration, excessive permissions, insecure APIs, exposed remote access, missing backups, poor network separation, weak encryption, vulnerable third-party software, and unsupported devices.

Be precise if asked: the checker covers configuration-level problems on machines. SQL injection and cross-site scripting live in website code; finding those needs a web-app test, which is on our roadmap as an import from tools like OWASP ZAP.

How we score risk

The score is a fixed formula, so the same inputs always give the same answer. The AI never changes a score.

Risk = 0.4 × Severity + 0.3 × Exposure + 0.3 × Criticality
  • Severity (0–100): how bad the weakness is, from the industry CVSS score × 10.
  • Exposure: internet-facing 90, reachable on the local network 70, internal 45, isolated 15. Unknown counts as 50 and is flagged, never treated as safe.
  • Criticality: how important the asset is to the organization. An asset inherits the importance of the most critical service that depends on it.
Critical 80–100 High 60–79 Medium 30–59 Low 0–29

Who should fix it

Fixed rules decide the label. Weak passwords, updates, backups and old devices: You can do this. Access rules, settings, remote access, encryption, network separation: Your IT person. Missing patches, vulnerable components, website flaws, insecure APIs: Call a professional. Anything scored Critical always says call a professional, with "limit access until then".

The AI

What it is

Foundation-Sec-8B-Instruct from Cisco's Foundation AI team, a security-tuned model built on Meta's Llama 3.1 8B. It runs through Ollama on our own laptop's GPU (about 5 GB). Users can switch models in the app.

What it does

  • Explains a problem in plain words
  • Reviews all problems: what to fix first
  • Reads the log summary: signs of attack, yes / no / unclear
  • Answers follow-up questions in a chat

What it does not do

  • It does not scan. The checker finds problems; the AI explains them.
  • It does not change scores or fix labels.
  • It does not invent findings: it is told to use only the scan data and to say when it doesn't know.
  • It refuses to help attack systems people don't own.

Privacy

Scan results and logs go only to the AI on our own machine, never to OpenAI or any cloud AI. With web search on, only the search words leave: the problem name or the question typed, plus the operating system (for example "SSH accepts passwords Ubuntu 24.04 how to fix"). Scan data and logs are never sent. Answers show the pages they used.

How our own product stays safe

Checker is read-onlyIt reads settings and logs only. --dry-run prints exactly what it would send. --no-logs skips logs. --uninstall removes it.
Only checks itselfThe checker reports on the machine it runs on. It never scans other machines on the network.
Accounts kept apartEach organization has its own data and its own access code. We tested that one account cannot see or scan another's machines.
Access codesA leaked code only lets someone send reports, not read anything. "Reset access code" turns old commands off.
Passwords and sign-inPasswords stored hashed (PBKDF2-SHA256, 200,000 rounds). Sessions are HttpOnly cookies that expire after 12 hours.
Public linkHTTPS through Cloudflare. While public: the demo password is replaced, "Scan this laptop" and model changes only work on the host laptop, and each account gets 20 AI requests per 10 minutes.
Web search safetyOnly public web pages are fetched; local and private network addresses are blocked.

Limits and roadmap

Judges respect honest answers. If a question touches one of these, say it plainly and say what's next.

Prototype limits today

  • Runs on one laptop; the public link changes each restart and needs the laptop on.
  • Data is stored in files, not a production database.
  • Firewall and backup checks are best guesses; cloud firewalls and provider backups can make them not applicable.
  • Doesn't test website code (SQL injection, cross-site scripting).
  • Windows needs Python installed, and its checks were mostly tested with simulated Windows outputs, so try them on a real PC before the demo.
  • Plans are sample pricing; no payments.
  • Score weights are illustrative and need calibrating with real pilots.

Next steps

  • Hosted service with a database and our own domain
  • One-click installers for Windows and Linux
  • Import findings from Greenbone, Wazuh and OWASP ZAP
  • Email or WhatsApp alerts for serious problems
  • Team roles and multi-site organizations
  • Reports that support good practice under India's DPDP Act (not a compliance guarantee)
  • Pilots to measure time-to-fix and calibrate the score
